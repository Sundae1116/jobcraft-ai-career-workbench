# JobCraft AI 求职决策工作台

**JobCraft 是一个帮助求职者高效寻找工作、管理目标岗位并自动定制简历的 AI 求职工作平台。** 使用者只需粘贴招聘官网链接，系统即可一键采集岗位名称、公司、地点、工作职责和任职要求等关键信息；随后以岗位要求为目标，反向检索使用者的真实工作经历、项目、作品和量化成果，分析匹配度与证据缺口，并自动生成针对该岗位的专属简历。

生成之后，使用者可以逐条核对简历修改内容、证据来源和风险提示。确认没有问题后，即可一键进入投递流程：锁定已确认的简历版本、准备常用申请字段、打开岗位官网并辅助填写。为保护求职者，薪资、工作授权、法律声明等敏感信息以及最终的“提交申请”仍需要本人确认。

JobCraft 把“发现岗位—判断匹配度—补全证据—自动定制简历—人工审核—投递准备—面试复盘”连接成一条可追踪的工作流。它不是批量海投机器人，也不会为了提高分数替候选人编造经历。核心原则是：**一份真实的候选人证据库，生成多份针对不同岗位的简历版本；简历里的每项主张都必须能追溯到证据 ID。**

> 仓库提供完整产品源码、确定性演示数据、招聘页适配逻辑、PDF 生成与安全的浏览器辅助扩展。

## 一条完整的求职链路

```text
粘贴目标岗位官网链接
        ↓ 一键采集
提取岗位信息与招聘状态
        ↓ 自动分析
将岗位要求反向匹配个人经验和证据
        ↓ 发现差距
显示最强匹配项、可迁移经验、待强化项和硬缺口
        ↓ 自动定制
生成岗位专属简历及修改建议
        ↓ 本人确认
锁定简历版本并进入官网辅助投递
```

对于求职者来说，JobCraft 不只是“写简历”，而是把每个目标岗位变成一项可以管理的求职任务：岗位信息不会散落在浏览器标签页里，不同公司使用的简历不会混淆，已经失效的岗位会被提前提示，新增证据可以同步改善后续岗位的匹配与简历质量。

## 核心使用价值

- **找岗位更高效**：一个工作台集中保存、归类、去重和跟踪目标岗位。
- **看岗位更准确**：自动拆解 JD，明确岗位真正需要的能力、行业背景、作品和结果。
- **改简历更有针对性**：不是套模板或堆关键词，而是根据每个岗位反向选择最相关的真实经历。
- **补证据更有方向**：想达到更高匹配度时，系统会指出缺失证据链，需要本人补充事实。
- **投递更连贯**：从岗位分析、证据补全、简历确认到官网辅助填写保持同一条记录。
- **面试准备更一致**：简历、30/90 秒介绍和面试问答引用同一套证据，减少前后矛盾。

## 产品解决什么问题

传统简历工具往往只润色文字，却没有回答：岗位值不值得投、哪些经历真正匹配、达到目标分数还缺什么证据、每句改写是否夸大。求职者往往需要在招聘网页、原始简历、多个 Word/PDF 文件和投递记录之间反复切换，既耗时，也容易给不同公司投错简历。

JobCraft 把岗位要求拆成能力域，将事实分为“直接支持、可迁移、待强化、硬缺口”，先暴露缺口，再决定简历保留、改写或压缩什么。系统追求的是更高质量、更有证据的精准投递，而不是盲目增加投递数量。

## 主要功能

### 官网岗位读取与标准化

- 粘贴官网链接，读取公司、岗位名称、地点、职责和任职要求。
- 支持 Moka 多方向职位页，候选人需要选择其中的具体招聘方向。
- 内置 Moka 平台适配器与蚂蚁招聘页面处理逻辑，平台差异集中在 adapter 层。
- 读取失败时允许手工粘贴 JD；不登录、不绕过验证码、不规避网站限制。
- 根据平台岗位 ID、规范化 URL，以及公司/岗位/地点组合去重；重复读取会更新原岗位并明确提示。

### 岗位池与招聘状态同步

- 按公司分组展示岗位，并按录入时间排序。
- 单击切换，双击进入证据核对，右键可查看、打开官网或删除。
- 支持单个删除、批量删除、回收站恢复和 30 天保留逻辑。
- 删除岗位后保留关联申请、简历版本和审核历史，避免审计链断裂。
- 定期检查官网状态，岗位关闭或失效时提前提示。

### 唯一事实证据库

- 管理工作经历、项目、作品、数字结果、来源材料与可信状态。
- 支持修改已有证据和新增经历；新增时检查同公司、同岗位、同时间段的相似记录并建议合并。
- 每条证据使用稳定 ID（如 `EV-008`），供评分、简历与审核引用。
- 区分已验证、本人陈述和待验证，不把待验证作品写成已完成成果。

### 可解释的岗位匹配

- 将岗位拆成能力、场景、行业、结果和作品要求。
- 将证据分成充分覆盖、可迁移、待强化和硬缺口。
- 展示最强匹配证据、匹配原因、可信度和下一步动作。
- 支持设置匹配度目标；目标高于证据上限时要求补充真实证据，而不是自动“优化”到目标分。
- 零硬缺口不等于完全匹配，系统仍提示弱证据和待核验项。

### 岗位版简历与差异审核

- 从同一证据库生成平衡版、强转型版等岗位专属版本。
- 提供 ATS、产品、作品集模板方向。
- 生成内容保留证据 ID 映射；差异审核支持保留、改写、压缩并给出建议。
- 用户确认后锁定具体简历版本，后续投递不会悄悄切换。
- 支持一张个人形象照、PDF 生成和两版简历并排预览。

### 申请、投递准备与面试材料

- 创建申请草稿后进入对应简历审核，不产生无后续的孤立记录。
- 使用 append-only 事件记录申请状态变化。
- 生成投递前检查清单、30/90 秒自我介绍、证据型面试问题和反问问题。
- 浏览器扩展只辅助普通字段；薪资、工作授权、法律声明等必须本人确认。
- 系统不会点击最终提交按钮。

## 产品优势

| 优势 | 具体体现 |
| --- | --- |
| 事实优先 | 简历主张必须引用证据 ID；缺证据时暴露缺口，不编造经历 |
| 决策可解释 | 展示岗位输入、评分、匹配证据、缺口、输出和人工闸门 |
| 一人一库，多岗多版 | 一套候选人事实生成多个互不矛盾的岗位版本 |
| 高匹配而非海投 | 先筛低价值岗位，再集中准备高潜岗位 |
| 本地优先 | 本地证据引擎无需外部模型或 API Key |
| 模型中立 | OpenAI、DeepSeek 与本地规则引擎位于统一 provider 接口之后 |
| 可扩展 | 招聘平台差异封装在 adapter 中 |
| 可恢复、可审计 | 回收站、版本、申请事件与人工确认保留决策上下文 |

## 适用场景

- 被裁员或准备集中求职，希望快速建立有秩序的投递节奏。
- 产品、运营、内容、AI 产品等跨职能候选人，需要把旧经历翻译成新岗位语言。
- 同时申请多个相似岗位，需要避免简历版本互相矛盾。
- 经验丰富但证据分散，希望整理作品、数字结果和来源材料。
- 希望使用 AI 改写，同时严格控制夸大和虚构。
- 将求职工作流作为产品设计、Agent、数据模型或人机协作案例研究。

不适合：匿名批量海投、验证码绕过、自动回答法律或合规问题、无人确认的最终提交。

## 快速开始

环境要求：Node.js `>= 22.13.0`、npm。Cloudflare Wrangler/D1 仅部署时需要；OpenAI 或 DeepSeek API Key 为可选项。

```bash
git clone <your-repository-url>
cd jobcraft-ai-career-workbench
npm install
npm run dev
```

根据终端提示打开本地地址。首次启动使用演示数据，不需要第三方账号。

```bash
npm run dev          # 本地开发
npm run build        # 生产构建
npm test             # 构建 + 回归测试
npm run lint         # ESLint
npm run db:generate  # 生成 Drizzle 迁移
```

## 使用方法

1. **建立证据库**：录入真实经历、项目、作品、数字结果和来源。
2. **新增目标岗位**：粘贴官网链接；无法公开读取时手工粘贴 JD。
3. **确认岗位方向**：多方向页面必须选择具体岗位，不能拿整个团队页匹配。
4. **查看岗位判断**：先检查招聘状态，再看最强证据、可迁移项和硬缺口。
5. **设定目标分数**：高于当前证据上限时，按提示补充真实材料。
6. **核对证据**：修订、验证或合并事实，确认哪些内容允许进入简历。
7. **生成简历计划**：选择策略和模板，逐条审核保留/改写/压缩。
8. **确认版本**：锁定审核通过的版本，生成 PDF 或投递准备包。
9. **创建申请草稿**：记录申请阶段，完成人工确认。
10. **打开官网投递**：浏览器助手减少重复输入，最终提交由本人完成。

## 模型与 API Key

- 默认本地证据引擎不需要 API Key。
- OpenAI/DeepSeek Key 只在模型请求时使用。
- 选择“记住”后，Key 保存在当前浏览器 `localStorage`，不会写入候选人数据库。
- 公共电脑请勿保存 Key；不要提交 `.env`、浏览器数据或真实密钥。
- 外部模型只能重组、压缩和翻译已有事实，不能新增不存在的经历。

## 数据、隐私与安全边界

GitHub 快照已移除个人简历 PDF、部署标识和真实联系方式，并使用演示身份。实际使用时：

- 将真实简历、照片、生成文件和数据库放在私有存储中。
- 不提交 `data/private/`、`data/generated/`、`.env*`、`.wrangler/` 和构建归档。
- 对岗位网页按不可信输入处理，不把网页内容当作系统指令。
- 不解决 CAPTCHA，不规避访问/频率限制，不自动最终提交。
- 薪资、工作授权、法律声明等敏感问题必须明确确认。
- 招聘状态同步只是带时间戳的观察，不保证绝对实时。
- 匹配分数代表证据覆盖度，不是录用概率。

## 浏览器辅助扩展

扩展源码位于 `extension/`。它只对清单中声明的招聘域名生效，只填写普通字段；遇到薪资、验证码、法律声明或工作授权时停止；不调用表单 `submit()`，也不点击提交按钮。

在 Chromium 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，指向 `extension/` 即可。

## 技术架构

```text
招聘官网 / 手工 JD
        ↓
岗位适配器与标准化
        ↓
去重、状态同步、硬条件筛选
        ↓
能力域匹配 ← 唯一候选人证据库
        ↓
岗位版简历计划 → 差异审核 → 版本锁定 → PDF
        ↓
申请事件、投递准备、面试材料、结果复盘
```

技术栈：React 19、Next.js 16、vinext、TypeScript、Drizzle ORM、SQLite/Cloudflare D1、PDF-Lib、Cloudflare Workers。

```text
app/                    页面与 API Routes
lib/job-adapters/       招聘平台适配器
lib/job-match.ts        能力域匹配与缺口分析
lib/resume-engine.ts    证据约束的简历生成
lib/model-providers.ts  模型中立接口
db/ + drizzle/          数据模型与迁移
extension/              安全填表助手
tests/                  工作流回归测试
skills/                 可安装的 Codex skill
docs/                   产品与岗位读取说明
```

## Codex Skill

`skills/jobcraft-career-workbench/SKILL.md` 可复制到 Codex skills 目录。启用后，Codex 在岗位分析、证据整理、岗位版简历和投递准备任务中会遵守 JobCraft 的事实约束与人工确认规则。

## 当前限制

- 招聘页结构经常变化，新增平台仍需要 adapter 或公开结构化接口。
- 部分动态页面只能在浏览器环境读取，服务端抓取未必获得完整正文。
- 本项目不会代替求职者做法律、薪资或身份声明。
- 当前是单候选人工作台；多人 SaaS 还需要租户隔离、权限、配额和数据保留策略。
